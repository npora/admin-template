# MySQL 权限模型初始化

适用数据库：MySQL 8.0.16+，InnoDB，utf8mb4。本目录是正式脚手架内容，与展示页面和可选测试后端独立。

## 执行顺序

在自己新建的空数据库中，依次执行：

| 文件                                         | 内容                                                      |
| -------------------------------------------- | --------------------------------------------------------- |
| [01-schema.sql](01-schema.sql)               | 六张业务表、索引、外键和状态约束                          |
| [02-seed.sql](02-seed.sql)                   | 总部、三种基础角色、系统管理菜单、18 个按钮权限及角色授权 |
| [03-dictionaries.sql](03-dictionaries.sql)   | 字典两张表、基础选项、菜单与八个按钮权限                  |
| [04-query-indexes.sql](04-query-indexes.sql) | 核心列表、树形查询与状态筛选的联合索引                    |

也可以在数据库工具里选择目标数据库后，按上述顺序导入四份文件。已有前两份初始化数据的库仅按顺序执行新增的第三、四份，每份一次。脚本不指定个人数据库名，不会连接展示服务，不会执行删表、覆盖或清空数据。

例如，先创建并选择一个新库：

```sql
CREATE DATABASE npora_admin
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;
```

在仓库根目录通过命令行分别导入；用户名和数据库名按自己的环境替换，密码由客户端提示输入：

```sh
mysql -u root -p npora_admin < database/mysql/01-schema.sql
mysql -u root -p npora_admin < database/mysql/02-seed.sql
mysql -u root -p npora_admin < database/mysql/03-dictionaries.sql
mysql -u root -p npora_admin < database/mysql/04-query-indexes.sql
```

按编号逐份执行，前一份成功后再执行下一份。每份仅执行一次，不加 `--force` 忽略错误；GUI 导入也应遇错停止。建表遇到同名表会报错，基础数据遇到重复主键或角色编码会报错，不会自动覆盖已有数据。种子数据在事务中导入，失败应回滚；MySQL DDL 隐式提交，结构和索引迁移不能依赖事务回滚，执行中断后应检查已完成步骤。已有业务库使用尚未应用的新增迁移，不能重新执行初始化文件。

## 八张业务表

| 表               | 用途                                                   |
| ---------------- | ------------------------------------------------------ |
| `sys_user`       | 用户、所属部门、密码哈希、账号状态及独立超级管理员标记 |
| `sys_department` | 部门树与部门资料                                       |
| `sys_role`       | 角色编码、名称和状态                                   |
| `sys_menu`       | 目录、页面、动态路由信息和按钮权限码                   |
| `sys_user_role`  | 用户与角色的多对多关系                                 |
| `sys_role_menu`  | 角色与菜单、按钮权限的多对多关系                       |
| `sys_dict_type`  | 字典编码、名称、状态与排序                             |
| `sys_dict_item`  | 字典标签、值、颜色与所属类型                           |

数据库列使用下划线命名；前端 DTO 使用驼峰命名，由后端映射。唯一约束保留软删除记录，删除用户或角色不会自动释放其唯一编码。

## 初始化后的权限

| 角色     | 初始能力                                 |
| -------- | ---------------------------------------- |
| `admin`  | 全部系统管理菜单及按钮权限               |
| `editor` | 用户查看、新增、编辑；不含删除或分配角色 |
| `viewer` | 只查看用户列表                           |

执行三份 SQL 后共 32 个菜单/权限节点、40 条角色授权。菜单包含用户、部门、角色、菜单、字典管理；不包含表格、下载或其他演示页面。每种角色的授权均包含所需祖先目录。表单示例、首页等静态页面不由此 SQL 创建。

`admin` 是普通角色编码，不自动代表超级管理员。后端应以用户的 `is_super_admin` 标记决定是否返回通配权限，并在每个接口独立校验有效角色、权限、账号状态和软删除状态。

## 用户与登录

正式初始化不预置用户或通用密码哈希，因此 `sys_user`、`sys_user_role` 初始为空。管理员账号由所接后端的初始化流程创建，同时写入密码哈希和用户角色关系。需要超级管理员时，由后端初始化流程设置其独立标记。

不同后端可能使用不同密码算法，不能把展示站的密码哈希直接复制进来。README 的 `admin / 123456` 只代表展示站的演示账号，不是执行本 SQL 后自动创建的数据库账号。

导入 SQL 即可建立权限模型和基础授权；前端登录仍需后端实现 [接口契约](../../docs/api.md) 中的认证、用户资料和动态路由接口。会话、令牌与登录限流的存储由自己的后端选择实现，不强制增加到这八张业务表。

## 字典增量升级

已有前两份初始化数据时，只按顺序执行 [03-dictionaries.sql](03-dictionaries.sql)、[04-query-indexes.sql](04-query-indexes.sql)，每份一次；不要重新导入旧的建表与种子文件。字典业务规则和前端使用方式见 [字典管理](../../docs/dictionaries.md)。

字典菜单和按钮不使用固定主键，ID 由数据库自增生成，再按唯一的 `SystemDict` 路由名称关联按钮和管理员授权。已有自定义菜单或软删除记录不需要让出 ID。已经成功执行字典迁移的数据库保持现有记录，无需重新执行此文件。

## 索引与查询

| 查询                         | 索引设计                                                              |
| ---------------------------- | --------------------------------------------------------------------- |
| 用户按部门、未删除条件查询   | `(department_id, deleted_at, id)`                                     |
| 用户按状态分页               | `(deleted_at, status, id)`；无状态时保留删除时间索引及其隐含主键      |
| 部门、菜单按父节点排序       | `(parent_id, deleted_at, sort_order, id)`                             |
| 角色、部门、菜单默认排序列表 | `(deleted_at, sort_order, id)`                                        |
| 角色、部门按状态排序列表     | `(deleted_at, status, sort_order, id)`                                |
| 字典类型列表                 | `(deleted_at, sort_order, id)` 和带 `status` 的对应索引               |
| 字典数据分页、选项、条数统计 | `(dict_type_id, deleted_at, sort_order, id)` 和带 `status` 的对应索引 |
| 编码或字典值精确定位         | 字典编码唯一键、`(dict_type_id, value)` 唯一键                        |

`04-query-indexes.sql` 用联合索引替换被覆盖的旧单列索引，外键关联列保留为索引最左列。两张权限关联表已有正反方向索引，保持原样。字典索引随 `03` 建表提供，不在 `04` 重复增加。

状态可选时，有状态与无状态查询分开组织条件，避免 `status = ? OR ? IS NULL` 妨碍索引选择。排序使用 `sort_order, id` 保证稳定分页。包含式关键词搜索（例如 `%关键词%`）仍需扫描候选记录，普通 B-tree 索引不解决任意子串搜索；当前实现不声称关键词查询无扫描。接入真实后端后用 `EXPLAIN` 结合实际数据量复核。

## 验证记录

2026-11-11，在隔离的 MySQL 9.6 临时实例中按顺序执行四份 SQL 成功，核对 32 个菜单/权限节点、40 条授权和两个字典选项，验证了字典值唯一约束、状态检查、关联删除限制及索引迁移。未连接或修改现有业务库。字典查询另在 SQLite 的执行计划中验证了联合索引及无临时排序；最低兼容版本 8.0.16 仍未实机验证。

2026-11-10，在隔离的 MySQL 9.6 临时实例中执行两份 SQL 成功，验证了六张表、23 个菜单/权限节点、31 条角色授权，无演示用户或示例页面，外键和状态约束生效，重复导入报错且未改变已有权限数据。未连接或修改现有业务数据库；最低兼容版本 8.0.16 尚未在本轮实机验证。
