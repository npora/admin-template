# 架构与模块职责

## 依赖方向

`views` 和 `layout` 负责渲染与交互，通过 composable、store、API 或会话服务获取能力。`api` 负责传输、协议与接口 DTO，不导入 Router、Pinia 或 Element Plus。`services/session.ts` 编排用户资料、权限、动态路由和会话清理；`useSession` 只负责在组件中获取当前 Router 的服务。

`store` 保存跨页面状态，页面的筛选、分页和弹窗状态留在对应业务目录。`utils` 提供小型、无业务 UI 的工具；界面选项放在 `constants`，请求与响应数据类型放在 `api/types`。

模板保留按职责分层的结构，不要求每个页面都建立独立 store、service 或通用组件。只有存在实际复用时再提取。

## 启动与清理

`main.ts` 创建应用，`bootstrap.ts` 安装 Pinia、恢复应用设置、安装指令和路由。应用卸载时移除路由相关订阅、系统主题监听和设备监听；开发模块整体替换时卸载旧实例。

`config/app.ts` 集中提供应用标题、API 前缀与 Mock 开关。代理与浏览器共用同一个 API 前缀规范化函数，避免配置不一致。

## 会话与路由

登录接口返回 Token，随后并行加载用户资料和授权路由。所有动态路由通过页面入口白名单转换，并在完整校验名称、路径冲突后注册到 `Layout` 下；失败会清理会话。目录不增加 RouterView 层级，默认重定向至第一个子路由。

会话服务按 Router 实例保存初始化任务和路由移除函数。同一会话的初始化请求共用 Promise；Token 被替换、退出或切换账号时，旧任务不能回写新会话。

静态路由只包含登录、Layout、首页、404 和未知地址兜底。菜单由静态路由和本次授权路由生成。用户直接进入深层地址时，加载动态路由后会重新匹配原地址。登录回跳仅接受站内地址，并排除登录页循环。

## 请求与错误

`publicRequest` 处理公共接口，`request` 注入 Token、执行受控重试。错误插件验证默认业务协议，在最终请求结束后通知由路由层注入的处理器。请求层与 UI 保持分离。

HTTP 401 或默认业务失效码会清理会话并回到登录页。并发失效通过 Token 版本去重；已经重新登录后，迟到的旧请求不影响新会话。403 不清理会话，取消请求不提示，静默选项只关闭通知。当前不支持 refresh-token 接口；用户菜单的“刷新权限”会重新获取资料与路由，不是自动刷新 Token。

## 标签与缓存

页面登记位于主内容区，独立于标签栏显示状态。标签负责地址与操作，`views` store 保存缓存标识、刷新版本和缓存包含列表。固定标签在深层页面首次进入时初始化。

缓存按 `path` 区分：不同参数路径有不同实例；同一路径的 query/hash 变化复用实例，标签记录最后访问的完整地址。主内容区为每个路径创建具名包装组件，因此无需让业务组件名与路由名一致，也能分别淘汰同一组件的不同路径实例。

页面过渡在 `RouterView` 插槽中使用 `Transition → KeepAlive → 具名页面包装组件`，参照 [Vue Router 官方组合方式](https://router.vuejs.org/guide/advanced/router-view-slot.html#keepalive-transition)。包装组件提供单一 DOM 根节点，兼容多根业务页面；只有路径或刷新版本变化触发切换，同一路径的 query/hash 更新复用页面。动画样式集中在 `src/assets/styles/transition.scss`，内容区先淡出再轻微上移淡入，侧栏和顶栏保持稳定；系统开启减少动态效果时关闭动画。

隐藏页面不显示菜单或标签，但仍可缓存。关闭标签淘汰对应缓存，刷新先移除旧实例再重建；退出登录清理全部标签与缓存。缓存不跨浏览器刷新持久化。

## Mock 与测试

Mock 位于 `mock`：`rbac` 保存按 SQL 列名定义的六张内存表、DTO 映射和授权计算，`identity.ts` 将 Token 关联到有效用户，`modules` 实现接口，`utils.ts` 统一响应与权限校验。Mock 通过开发分支动态导入；生产构建不加载 Mock 模块。

集成检查位于 `tests/integration`，共用 `tests/helpers/environment.mjs` 的内存存储、Router 和 Vite 转换环境，不启动 HTTP/WebSocket 服务。每个测试 Vite 实例使用独立临时 `cacheDir`，关闭后清理，并禁用不需要的客户端依赖扫描；测试不能复用开发服务的 `node_modules/.vite`。缓存检查使用 Vue 真实渲染器检查组件实例的保留和销毁；`transitions.test.mjs` 还会推进真实 Vue CSS 过渡钩子的异步阶段，验证不缓存首页与缓存管理页互相切换、快速导航和动画结束后的页面点击；这些检查不替代真实浏览器的布局验收。

## 前端示例与本地资料

表格与分步表单的演示模型位于各自页面目录，不进入 API/Mock 层；通用工具栏、分页和查询状态作为共享组件与 composable 复用。个人资料模型和持久化集中在 `store/modules/profile`，用户 store 的显示名称/头像可读取本地资料，但认证资料保持原值。静态表单和个人中心仅要求登录，业务管理页仍使用动态菜单授权。首页可访问页面数量根据静态页面与已授权动态页面计算。详见 [前端示例说明](examples.md)。

## 可移除的演示模块

`mock/` 与 `workers/api/` 放在前端源码外；前端只引用可选 Mock 虚拟适配器，不导入这两个目录的实现。Mock 类型与集成测试跟随 Mock 目录维护，Worker 使用独立包和测试，不参与前端构建。删除两者后，前端类型检查、核心测试和生产构建均可独立运行。详见 [接入自有后端](backend-replacement.md)。

## 刷新时的启动加载层

`src/startup/loading.html`、`loading.css`、`loading.js` 由 `build/app-loading.ts` 内联到 HTML，在 Vue 主模块加载前显示品牌标识、呼吸效果与不定进度光带，不依赖业务 JS、Mock 或 Worker。首屏恢复保存的明暗主题，主模块启动后使用当前 i18n 文案；HTML 的中文提示只作为模块尚未就绪时的兜底。

`main.ts` 保留加载层直到 `router.isReady()` 与下一次 DOM 更新完成，覆盖登录恢复、动态路由和首个页面模块的等待时间，然后淡出并释放键盘交互、计时器和错误监听。页面内数据请求继续使用各自的 skeleton/loading，不人为延长启动动画。

超过 15 秒提示等待或重试，成功后仍可继续进入；模块、样式或启动过程失败时显示重新加载入口，防止永久空白。遵循系统减少动态效果设置。
