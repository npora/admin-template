# 多语言

默认提供简体中文（`zh-CN`）和英文（`en-US`），使用 Vue I18n 的 Composition API。多语言配置集中在 `src/config/i18n.ts`，不需要修改 `.env`，也不需要后端。

## 配置

```ts
import { registeredLocales } from '@/locales/registry'

export const i18nConfig: I18nConfig = {
  enabled: true,
  defaultLocale: 'zh-CN',
  fallbackLocale: 'zh-CN',
  supportedLocales: [...registeredLocales],
  detectBrowserLanguage: false
}
```

- `enabled`：控制是否允许用户切换语言。关闭后隐藏登录页、顶栏和设置中的语言入口，忽略保存的偏好，固定使用默认语言。翻译插件仍安装，页面继续使用同一套 `t()` 调用。
- `defaultLocale`：首次访问、保存值无效或关闭多语言时使用的语言。
- `fallbackLocale`：当前语言缺少词条时使用的回退语言。
- `supportedLocales`：用户可选择的语言白名单，默认从注册表生成，也可显式限制为部分已注册语言；必须包含默认和回退语言。只保留一种语言时不显示下拉切换按钮。
- `detectBrowserLanguage`：没有有效保存值时匹配浏览器语言列表，优先匹配完整语言标签，再匹配语言前缀。

开启时优先级为：有效用户偏好 → 浏览器语言（开启检测时）→ 默认语言。使用现有带前缀的 localStorage 服务保存 `locale`，存储不可用时降级为当前页面内存。切换语言不会退出登录、重置权限或清空页面缓存。设置中的“恢复默认设置”同时清除语言偏好并重新应用默认选择策略。

构建中显式关闭未使用的 Legacy API，保留 JSON 词条所需的消息编译器，参照 [Vue I18n 构建优化说明](https://vue-i18n.intlify.dev/guide/advanced/optimization)。

配置属于代码配置，生产修改后需要重新构建。当前两套语言资源随应用一起加载；关闭开关表示固定语言，并不表示从产物中移除 Vue I18n 或其他语言包。

## 目录与用法

```text
src/config/i18n.ts           开关、默认语言与白名单
src/locales/
  registry.ts               唯一语言注册入口，推导 AppLocale 类型和资源列表
  types.ts                  语言包完整性契约与翻译结构
  index.ts                  i18n 实例、语言应用、路由标题与日期/数字/列表格式
  policy.ts                 语言优先级与有效值校验
  errors.ts                 前端通用错误消息翻译
  zh-CN/                    简体中文资源
  en-US/                    英文资源
    index.ts                该语言名称、资源、Element Plus、Day.js、日期格式
    ui.json                 页面、表单、提示等界面文案
    routes.json             模板内置路由名称
    language.json           语言选择文案
    errors.json             通用请求错误
    table.json              表格工具与下载示例
    form.json               分步表单与校验
    profile.json            个人中心与本地资料
src/store/modules/locale.ts 用户语言状态与持久化
src/composables/useLocale.ts Element Plus 语言及切换接口
src/components/LocaleSwitch/ 登录页与顶栏的共用切换器
src/types/i18n.d.ts          翻译词条类型提示
```

页面使用：

```vue
<script setup lang="ts">
import { computed } from 'vue'
import { useI18n } from 'vue-i18n'
import { formatDate } from '@/locales'

const { t } = useI18n({ useScope: 'global' })
const options = computed(() => [
  { label: t('ui.enabled'), value: 1 },
  { label: t('ui.disabled'), value: 0 }
])
</script>

<template>
  <span>{{ t('ui.usersInTotal', { value: 12 }) }}</span>
  <span>{{ formatDate('2026-11-09T15:05:00') }}</span>
</template>
```

翻译结果用于 `computed` 或渲染函数，避免在组件初始化时保存静态翻译字符串。表单规则和设置选项也使用响应式计算，缓存页面切换语言后可立即更新。新增词条应同步维护两种语言的键和命名参数；JSON 示例中的花括号等保留字符需要按 Vue I18n 的 literal interpolation 语法转义。

## 组件和日期

`App.vue` 的 `ElConfigProvider` 跟随当前语言，覆盖分页、日期选择器等 Element Plus 内置文案。切换时同步更新 Day.js 全局语言和 `document.documentElement.lang`。

页面统一使用 `formatDate(value, format)`，支持 `date`、`dateTime`、`short`、`time`、`heading`。中文默认 24 小时格式，英文默认英文月份与 12 小时格式；`heading` 使用当前语言的 `Intl.DateTimeFormat`。无值或无效日期显示 `—`，时间按浏览器所在时区展示，不改变接口时间值。Day.js 已启用 `localizedFormat`，可使用 `L`、`LL` 等本地化格式。

数值通过 `formatNumber(value)` 按当前语言格式化；列表通过 `formatList(values)` 使用对应语言的分隔方式。首页问候语、句尾标点和统计单位也由词条定义，业务页面不再通过 `locale === ...` 判断中文/英文。不要在业务页面重新硬编码 `zh-CN` 或固定英文日期格式。

## 路由与业务数据

菜单、面包屑、标签及浏览器标题在展示时翻译，不改变路由 ID、路径、名称、权限码或缓存键。内置路由通过路由名称关联 `routes.json`；无路由名称的内置目录使用默认目录标题匹配。修改过的菜单标题和自定义菜单标题保留原文，避免把业务配置覆盖成模板默认名称。新增内置路由时，应同步维护两套 `routes.json`。

用户姓名、角色名称、部门名称、权限码和其他业务数据不自动翻译。前端定义的通用网络、权限及登录过期提示已本地化；任意服务端或 Mock 业务错误详情仍按响应原文展示，后续可扩展稳定错误码到翻译键的映射。

## 新增语言与验证

增加语言时，复制一个语言目录，翻译对应的 JSON，并在该语言的 `index.ts` 中提供名称、Element Plus 语言包、Day.js locale 引入及日期格式。然后只需在 `registry.ts` 中导入并注册：

```ts
import jaJP from './ja-JP'

export const localeRegistry = {
  'zh-CN': zhCN,
  'en-US': enUS,
  'ja-JP': jaJP
} satisfies Record<string, LocaleDefinition>
```

`AppLocale`、默认可选语言、切换器选项、Vue I18n 资源和组件/日期联动均由注册表推导，不需要修改页面或给 `useLocale` 添加分支。如果配置中使用了显式白名单，需要将新语言加入白名单。语言包通过 `LocaleDefinition` 检查字段完整性；`LocaleMessages` 以中文词条结构为基准提供类型提示。中英文资源是模板当前完整支持的语言。

`pnpm run check:locales` 检查配置、偏好恢复、禁用开关、浏览器语言匹配、响应式翻译、Element Plus、Day.js、日期与数字格式、路由标题、通用错误以及所有注册语言的词条/参数一致性、前端引用缺失和无用 UI 词条。`pnpm run check` 包含该回归。

## 英文长文案布局

管理页标题和筛选操作支持换行；部门操作列与菜单类型列预留英文宽度。首页欢迎区按钮允许换行，统计单位由词条控制。弹窗底部按钮可换行，长校验提示参与表单布局，避免覆盖下一个字段。面包屑和菜单长标题使用省略显示并保留完整提示；设置抽屉宽度受视口限制。

代码与功能回归不替代浏览器验收。实际视觉检查应覆盖中文/英文、浅色/深色，以及桌面和 320/375px 小屏，尤其检查筛选按钮、分页、弹窗错误提示、授权树和缓存页面切换语言后的布局。
