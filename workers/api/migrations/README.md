# SQLite 迁移

首次空测试库按顺序执行：

1. `0001_schema.sql`：SQL 设计对应的六张业务表，加独立会话与登录限流表。
2. `0002_seed.sql`：部门、角色、菜单和授权种子，不包含用户或密码。
3. `0003_auth_revocation.sql`：账号禁用、软删除和密码变化时删除关联会话的触发器。
4. `0004_management_guards.sql`：业务版本触发器和事务门禁，防止校验与提交之间的数据竞态。
5. `0005_dictionaries.sql`：字典表、数据版本触发器、菜单权限与基础选项。
6. `0006_query_indexes.sql`：未删除记录、状态筛选和排序的核心联合索引，替换被覆盖的旧索引。
7. `0007_totp.sql`：可选验证器绑定、加密密钥记录、防重复使用状态及绑定变更时的会话撤销。
8. `0008_millisecond_timestamps.sql`：将旧 ISO 时间转换为整数毫秒并重建表，保留 ID、自增序号、数据关联、会话、索引及触发器。
9. `0009_sort_indexes.sql`：增加部门、角色、菜单的全量排序索引，完善会话保留查询的联合索引。
10. `0010_recent_users_index.sql`：新增未删除用户按创建时间和 ID 排序的索引。
11. `0011_audit_logs.sql`：新增操作审计表、查询索引、审计日志页面和独立查看权限。
12. `0012_session_management.sql`：为既有会话补齐独立管理 ID，扩展操作审计约束，新增会话管理和权限预览权限。
13. `0013_audit_lookup_indexes.sql`：增加操作者和目标 ID 的联合查询索引。
14. `0014_example_menu_root.sql`：将操作示例提到一级导航，保留原有访问路径和角色授权。
15. `../.local/bootstrap.sql`：`npm run bootstrap` 在本机生成的随机账号哈希与关联角色。

每份只执行一次；这些文件没有自动迁移执行器。后续已部署数据库的结构变更须新增编号迁移，执行前检查已应用版本，不改写旧文件、不重新初始化、不覆盖原表。

已有前六份迁移的库顺序执行 `0007_totp.sql`、`0008_millisecond_timestamps.sql`，已有前七份仅执行 0008。所有参考后端部署都需完成这些迁移，即使验证器默认关闭，登录事务仍检查绑定状态。配置与接口见 [登录与账号安全](../../../docs/authentication.md)。

0008 针对模板原始表结构，执行前暂停写入并备份，在单个事务中完整应用；D1 迁移事务负责原子执行，本地 SQLite 需在外层包裹 `BEGIN` / `COMMIT`，失败 `ROLLBACK`。不能拆开逐条执行。迁移先检查不可解析的旧时间、自定义列、命名索引/触发器和外部外键；存在自定义结构时应先适配迁移，不能删除业务数据来绕过检查。迁移复制数据后按依赖顺序重建表，恢复原有约束和模板索引/触发器，并检查外键。原会话过期时间与验证器到期时间已是毫秒，保持原值；`last_used_step` 是 TOTP 防重放计数，不是时间戳。

`database/mysql/01-schema.sql` 是 MySQL 设计文件，不能直接在 SQLite 中执行。本目录保留业务列名与软删除语义，将 MySQL 类型转换为 SQLite 类型；`route_query` 存 JSON 文本，所有绝对时间使用 `INTEGER` Unix 毫秒，`updated_at` 由写接口显式更新。未删除仍用 `deleted_at IS NULL`，时间戳 `0` 不等于未删除。SQLite `NOCASE` 只对 ASCII 大小写生效，不能假定等同于 MySQL 的 Unicode 排序规则。用户名限制为字母开头的 ASCII 字母、数字和下划线，长度 3–64。

唯一约束包含软删除行，删除账号不会释放用户名。前端 DTO 使用驼峰命名，由服务端映射，不直接输出数据库行。

已有数据库只按编号应用尚未执行的迁移：已有前三份时依次应用 0004 至 0008；已有前四份时依次应用 0005 至 0008。不能重复执行旧建表、种子或 bootstrap。业务规则与接口见 [字典管理](../../../docs/dictionaries.md)。

0005 的字典菜单和按钮由数据库分配 ID，通过 `SystemDict` 路由名称建立父子关系和管理员授权，兼容已有自定义菜单及软删除记录。已成功应用旧版 0005 的库无需重跑或调整既有 ID。
